**Ескіз для дизайну (рекомендації до спеца; пункти про `stageBase` і страховку замінено C_CTX_DEC_15, межі — за §3.2 концепту після рев'ю 27):**
- Структура: відкритий етап у TagRegistry (`stage: { name, after: { anchor, hint } | null, opened_turn }`) і кінець останнього закритого (`closedEnd: { anchor, hint } | null`); ~~`stageBase`~~ (замінено C_CTX_DEC_15); етапи пласкі, без вкладення.
- `context_tag`: `op` `open` (поле `stage` — назва; необов'язковий `index` — перший рядок блоку) і `close`. Без `index` блок починається після рядка, що передує відповіді з викликом `open`. `open` при відкритому етапі спершу закриває поточний (з нагадуванням). `close` без відкритого етапу — помилка `NO_STAGE`.
- Межа зберігається як «після рядка X» (якір + hint), X — останній рядок перед рядком із викликом. X сам може зникнути або змінитися без правки агента (прибирання службових викликів, перезбирання відповіді, порожній рядок лише з thinking), тож при кожному застосуванні і засіві межа, чий рядок змінено, перезібрано або прибрано з будь-якої причини, переїжджає за найближчий попередній рядок, що лишився (RebindTags має рядки «до» і «після»), а не видаляється, як теги (концепт §3.2).
- Кінець блоку при закритті — рядок перед рядком із `tool_use_id` виклику `close`.
- Нагадування закриття: назва, межі, ≈ токени блоку (символи / 4), медіа; порада, як у NudgeText.
- ~~Страховка: ріст = `Messages` − `stageBase`~~ (замінено C_CTX_DEC_15) (`stageBase` ≤ поточного розміру); текст просить закрити завершений етап або стиснути наступну порцію з початку.
- `context_list`: у заголовку відкритий етап і його початок; позначка `[stage ▶ name]` на першому рядку блоку.
