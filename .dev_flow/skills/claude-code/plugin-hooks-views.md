# Моди Claude Code: подання розмови: `$.session.messages()`, `{ as: 'api' }`, `e.messages`, вікна, медіа, вкладення, доставки, рядки `isMeta`

Тематичний файл навички [ClaudeCodePluginHooks](plugin-hooks.md): пункти 10, 13, 15, 17, 43, 46, 47, 48, 49, 50, 52, 59, 72, 73, 75 її списку пасток, дослівно і з тими самими номерами (якір `#p<N>`), тож посилання «plugin-hooks N» / «навичка, пункт N» ведуть сюди через [покажчик](plugin-hooks.md#pitfalls). Посилання «пункт N» у тексті — на номер у тому самому списку, хоч би в якому тематичному файлі він лежав.

## Applicability Boundary

- **when_to_use:** пишете або змінюєте мод у `mods/` і зачіпаєте цю тему (подання розмови).
- **when_not:** класичні хуки `settings.json` (команди оболонки) — інший механізм.
- **version_or_context_scope:** версії хоста, на яких перевірено кожен пункт, — у [вхідному файлі](plugin-hooks.md#applicability-boundary); `state: stale` — на встановленому хості 2.1.299 і хості VS Code 2.1.301 пункти не перезвірено (рішення про перезвірку наживо — за розробником).

## Pitfalls

<a id="p10"></a>
10. **`$.session.messages()` і `{ as: 'api' }`** віддають до 4096 останніх рядків/повідомлень; медіа видно лише в API-поданні. Вхід `session.compact` (`e.messages`) цього ліміту не має (пункт 49).

<a id="p13"></a>
13. **`$.session.messages()` повертає весь транскрипт, разом з рядками до межі компактизації**: після компактизації від обробника старі рядки йдуть першими, далі їхні копії. Позначки межі в `SessionMessage` немає, і `session.append` рядків компактизації не бачить; `{ as: 'api' }` дає лише те, з чого збирається наступний запит. Вхід `session.compact` (`e.messages`) — лише хвіст транскрипту після останньої межі (і для `/compact`), а повернені рядки стоять у наступному читанні суцільним блоком з тими самими відбитками: на цьому стоїть межа поточної розмови редактора (SP_CTX_DEC_07). Перевірено на 2.1.295.

<a id="p15"></a>
15. **Медіа від вбудованого Read не буває великим**: зображення понад ~0.5 МБ він перекодовує в JPEG, а великий PDF (4.6 МБ) віддає сторінками-JPEG, не блоком `document`; малий PDF приходить блоком `document` з `source.type = base64`. Тестувати багатомегабайтний `stdin` треба через інший шлях (напр. архів кількох медіа одним пакетом).

<a id="p17"></a>
17. **Транскрипт сесії — `~/.claude/projects/<cwd з не-буквено-цифровими символами → '-'>/<id>.jsonl`, API для шляху немає.** `--resume` приймає зібраний поза хостом файл; обов'язкові поля рядків `user`/`assistant` — `type`, `uuid`, `parentUuid`, `timestamp`, `message`; модель бачить лише `message.content` (`toolUseResult` — для інтерфейсу). Без `timestamp` — «No conversation found», а розірваний ланцюжок `uuid`/`parentUuid` дає **тиху** порожню розмову. Деталі й збирач — спайк `docs/context_editor_session.spike.md`, `.dev_flow/cache/session-transcript/`.

<a id="p43"></a>
43. **Доставки посеред ходу — вкладення `queued_command`, а не рядки** (2.1.295, обидва хости, спайк `docs/context_editor_attachments.spike.md`). Повідомлення людини, набране під час ходу, звіт субагента й сповіщення фонової задачі приходять у запущений хід лише на межі виклику інструмента: запис транскрипту `type: "attachment"`, `attachment.type: "queued_command"` (`origin.kind` `human`/`peer`/`task-notification`, сирий `prompt`, `rendered[0].content` — рядок або блоки, `renderedRole: "system"`), батько — рядок з `tool_result`. Модель отримує його системним ходом, тож його немає ні в `$.session.messages()`, ні в `e.messages` обробника `session.compact`, ні в `{ as: 'api' }`. Бачать його лише `session.append` (`door: 'delivery'`, `type: 'attachment'`, `name: 'queued_command'`, `content` — відрендерений текст; попередній рядок у порядку подій — якір `tool_result`) і `prompt.submit` з `turnId` ходу (сирий текст). Коли сесія вільна, сповіщення стає звичайним промптом-рядком.

<a id="p46"></a>
46. **Текст навички, відкритої `Skill`, — не рядок розмови** (2.1.295, stream-json, проба фази 15). Він проходить `session.append` окремим рядком `type: user`, `isMeta: true`, `door: tool-message`, `origin { kind: 'tool', tool: 'Skill' }` (поруч із коротким `tool_result` «Launching skill»), але в `$.session.messages()` і в `e.messages` компактизації його немає. Повторний `Skill` тієї самої навички в тій самій розмові хост удруге не вставляє: `tool-message` має лише «Skill /<name> is already loaded above; …» (73 символи). Slash-команда людини `/<name>` після `Skill` вставляє повний текст удруге (термінал, 2.1.295: двері `note`, `origin engine`, `isMeta`; теж не рядок `$.session.messages()`); після `/compact` хоста термінал показує «Skills restored».

<a id="p47"></a>
47. **Промпт людини з медіа в трьох поданнях** (2.1.296, обидва хости, спайк `docs/context_editor_media.spike.md`). `Row.text` — текстові блоки промпту, з'єднані без розділювача (`[text A, image, text B]` → `"AB"`); медіа немає; промпт лише із зображенням — `""` у stream-json і `"[Image #N]"` у терміналі (TUI пише заповнювач у текст); пробіли й `\n` на краях тексту зберігаються. `prompt.submit` дає той самий текст через `\n`. В `{ as: 'api' }` повідомлення промпту — злиття: вкладення хоста (`<system-reminder>…` текстовими блоками) перед блоками промпту, далі блоки промпту в початковому порядку, далі isMeta-нотатка `[Image: source: <шлях>]` на кожне зображення (`session.append` `door: note`, `isMeta`; не рядок `$.session.messages()`; у stream-json хост зберігає зображення в `/tmp/claude-<uid>/<cwd-slug>/<sid>/images/<n>.png`, у терміналі — шлях вставленого файлу). На стиках злиття хост іноді дописує `\n` у кінець текстового блоку — текст порівнювати без пробільних символів.

<a id="p48"></a>
48. **API-повідомлення `user` = відрізок суміжних рядків `user`, але не завжди.** Рядки команди (`<command-name>/compact…`, `<local-command-stdout>Compacted…`) зливаються з наступним промптом, і хост додає блок `<local-command-caveat>…`, якого в рядках немає. У терміналі `@файл` дає окреме API-повідомлення `user` лише з `<system-reminder>Called the Read tool…` (без рядка, не злите з сусіднім); `@image.png` кладе зображення файлу першим блоком у повідомлення промпту. Лічити промпти від початку в обох поданнях не можна; зіставлення від хвоста з перевіркою кожного ходу — спайк медіа. У stream-json `@файл` у тексті нічого не вкладає. Два промпти stream-json, надіслані підряд, поки сесія зайнята, хост зливає в один промпт і один рядок (2.1.296).

<a id="p49"></a>
49. **Межі вікон** (2.1.296, stream-json, 4214 рядків після межі): `$.session.messages()` — 4096 найновіших рядків усього транскрипту разом із рядками до межі; `{ as: 'api' }` — 4096 найновіших повідомлень від останньої межі, першим іде `user`; оскільки повідомлення зливають рядки, API-вікно сягає далі в історію, ніж вікно рядків; `e.messages` обробника `session.compact` — усі рядки після останньої межі, без ліміту (4214), кожен з `handle`. Хвости трьох подань збігаються, крім терміналу під час компактизації (пункт 50). Після вбудованої `/compact` рядки мають рядок `user` з підсумком і копію останньої відповіді асистента, API починається з підсумку; у терміналі рядок підсумку стоїть одразу після останнього рядка `user` до межі (один суцільний відрізок `user` у рядках).

<a id="p50"></a>
50. **Термінал: під час компактизації `$.session.messages()` і `{ as: 'api' }` закінчуються рядком промпту `/compact <args>`** (рядок поза ланцюжком, пункт 24), якого немає в `e.messages`; у stream-json його немає в жодному поданні. Код, що зіставляє `e.messages` з API-поданням від хвоста, мусить пропустити це повідомлення (2.1.296).

<a id="p52"></a>
52. **Посеред ходу (хук `tool.call`) `$.session.messages()` і `{ as: 'api' }` уже мають рядок поточного виклику** (`tool_use` без результату), тож їхні хвости збігаються і в мить виклику інструмента мода. Паралельні виклики рядки пишуть «виклик a, результат a, виклик b» (пункт 40), а API — одне повідомлення асистента з обома `tool_use` і одне повідомлення результатів: зіставляти подання треба ходами людини, а не окремими повідомленнями (2.1.296, stream-json, спайк медіа, Entry 4).

<a id="p59"></a>
59. **`prompt.attachment`: коли хост питає вкладення і що дає відповідь** (2.1.296, stream-json і термінал, haiku, спайк `docs/context_editor_host_attachments.spike.md`, сирі дані `.dev_flow/cache/live-test/host-attachments-spike/`). Хук отримує всі вкладення з текстом (`instructions`, `skill_listing`, `nested_memory`, `environment`, `date`, `*_delta`, `hook_additional_context` — і від хука налаштувань, `origin { kind: 'hook', event }`, і контекст плагіна з `prompt.submit`, `origin { kind: 'plugin', event: 'prompt.submit' }`); на вході лише `type`, `text`, `origin`, `agentId` — ні id, ні часу, ні шляху. Питає не на кожен запит: нове вкладення — один раз, коли з'являється (зокрема посеред ходу), далі відповідь тримається на процес; усі вкладення розмови перепитуються в порядку розмови (нове — останнім) після кожної компактизації (і від обробника, що повертає `e.messages` як є), після `$.ui.invalidate('prompt.attachment')` — з наступного ходу, не з поточного (виклик з `prompt.submit` ходу N діє на N+1; з обробника `session.compact` не відхиляється) — і в новому процесі після `--resume`. `{ text: null }` прибирає вкладення із тіла запиту, `{ text }` переписує (у журналі `--debug`: `prompt.attachment <type>: <plugin> (user) left it out (N characters)` / `rewrote it (A -> B characters)`); незмінні відповіді байтів не змінюють, змінена — переписує кеш від позиції вкладення (перша копія `instructions` лежить у першому повідомленні). `$.session.messages()` вкладень не має, `{ as: 'api' }` має (блоки `<system-reminder>` у повідомленнях `user`, уже з відповіддю хука); транскрипт зберігає запис рушія, тож після `--resume` без збережених рішень усе повертається. Після компактизації хост перечитує файли інструкцій з першим промптом після межі (не під час неї) і докладає лише змінені, повною копією з рамкою «Instruction files were re-read after the conversation was compacted … each replaces its earlier copy, and the instructions preamble above still applies»; секція `Contents of <path> (<опис>):\n\n<вміст>` збігається з файлом після `trim()`. Живий прогін фази 24 мода (2.1.296, обидва хости, `.dev_flow/cache/live-test/phase24-results.md`): (а) нову копію CLAUDE.md хост докладає **лише після компактизації**, ніколи на звичайному ході; (б) пізніші `skill_listing` — **інкрементні**: той самий заголовок «The following skills are available for use with the Skill tool:», але лише додані навички (~140 символів; у транскрипті `isInitial: false, skillCount: 1`), а хук бачить лише текст — тож «лишати найновіший перелік» прибирає повний; застарілим перелік робить лише новіший, що називає всі його навички (`- <name>:`).

<a id="p72"></a>
72. **`$.session.messages()` не повертає рядків `isMeta`** (зонд `.dev_flow/cache/live-test/hostrows-probe/`, хост 2.1.299, stream-json без мережі, 2026-10-15; спайк `docs/context_editor_hostrows.spike.md`). Розгорнута навичка («Base directory for this skill: …») приходить у `session.append` як `type: user`, `isMeta: true`, двері `note`, походження `engine`, звіт субагента між ходами — як `isMeta` з походженням `peer`; у перегляді `$.session.messages()` їх немає, а `$.session.messages({ as: 'api' })` несе розгорнуту навичку окремим текстовим блоком злитого повідомлення `user` (без рядків, яких немає в запиті, тож номерів рядків з неї не відновити). В `e.messages` обробника компактизації їх теж немає (`ledger.json` сесії 355660b2: 157 рядків входу, жодного `isMeta`); після того як обробник повернув рядки, хост сам ставить кожен рядок `isMeta` за видимим рядком, що стояв перед ним, якщо той повернувся з `handle`, а перебудований без `handle` чи прибраний попередник забирає його з собою. Промпт людини в stream-json приходить з походженням `unclassified` (двері `prompt` і `command`), а не `sdk`. Обробник `session.compact` плагіна з `--plugin-dir` на машині з керованими налаштуваннями хост пропускає й запускає власний підсумок (`compact_error` без мережі). Для мода: щоб агент бачив і стискав такі рядки, мод записує їх при `session.append` з `handle` попередника, показує окремим списком з `id` і прибирає `drop` за `id`, повертаючи попередника без `handle` (P24, SP_CTX_02_60–02_61, SP_CTX_DEC_42 B″).

<a id="p73"></a>
73. **Вставлений текст — у самому тексті рядка, в обгортці `<pasted_content id="X">…</pasted_content id="X">`** (фаза 39, 2.1.296 і 2.1.299, пробний плагін `.dev_flow/cache/live-test/curation-gate/paste-probe/`). Обгортку бачать `prompt.submit`, `session.append` (двері `prompt`), `$.session.messages()`, `{ as: 'api' }` і транскрипт. Обгорнуто: велику вставку в терміналі (згорнуту в «[Pasted text #1 +N lines]»; 12 рядків — так), поле stream-json `pasted_content` (масив; текст дописано після набраного через `\n\n`) і `inline_pastes` (масив рядків, що вже стоять у `message.content`; обгортка — на їхньому місці) — обидва поля описано в схемі введення SDK; розширення VS Code (OSS, 2.1.299 і 2.1.300) за своїм кодом (`webview/index.js`) шле вставки в `inline_pastes`, якщо віддалений прапор `tengu_vscode_inline_pastes` не `false` — наживо не спостережено. Коротку вставку в терміналі (не згорнуту) не обгорнуто (спостережено на 2.1.299): вона — звичайний набраний текст. Id — один на сесію (4 hex), тож блоки різнить лише порядок.

<a id="p75"></a>
75. **Повторне `Read` незміненого файлу — заглушка, а не вміст** (бінарник 2.1.299, рев'ю фази 43, 2026-10-16; наживо не прогнано). На `Read` з тими самими аргументами файлу, що не змінився з попереднього читання в цій розмові, хост відповідає текстом «File unchanged since last read. The content from the earlier Read tool_result in this conversation is still current — refer to that instead of re-reading.» без пронумерованих рядків. Порівнювати два читання за сирим текстом не можна: правило R6 (`changedRead`, [SP_CTX_02_65]) дивиться лише на пронумеровані рядки, а вивід без них тегу не дає. Стиснути раннє читання тут — значить прибрати єдину справжню копію.
