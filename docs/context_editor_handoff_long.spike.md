# Spike: Передача через транскрипт для довгих сесій і хостів без `/resume`

> **Status:** concluded
> **Created:** 2026-10-09
> **Updated:** 2026-10-09
> **Author:** Claude (Opus 5.5) разом з alexandr.yavorsky
> **Time-box:** 1 сесія
> **Scope:** codebase (код передачі, типи хоста, рядки бінарників хоста 2.1.289 і 2.1.295), prototype (одноразові плагіни й малі тестові сесії в scratchpad, `claude -p`, режим stream-json, tmux; жодного ходу на великій сесії)
> **Mode:** single
>
> **Target concept:** [C_CTX](./context_editor.concept.md)
> **Serves:** [C_CTX_DEC_11](./context_editor.concept.md#C_CTX_DEC_11) (передача в нову сесію), продовжує [спайк схеми B](./context_editor_session.spike.md)
> **Question(s):**
> 1. Чому спосіб «транскрипт» не спрацював на живій сесії 8e44a3be (VS Code, хост 2.1.289, транскрипт 5 МБ, ~554k токенів, 753 рядки `user`/`assistant`)? Чи справа в довжині сесії?
> 2. Чи можна в хості без `/resume` (режим stream-json, як у VS Code) передати новій сесії очищену розмову з парами викликів інструментів? Кандидат: `/clear` → `session.compact` з другого плагіна → обробник редактора повертає зібрані рядки. Чи бачить модель саме їх, і що покаже `--resume` цієї нової сесії?
> 3. Як зібрати записи для сесії, де модель бачить не всі рядки (після компактизації хоста або понад вікно 4096 рядків `$.session.messages()`), замість відмови? Чи годиться для цього API-подання (підсумок компактизації і хвіст), і чи приймає `--resume` транскрипт, що починається з підсумку?

## Context

Живий тест передачі ([фаза 9 PL_CTX](./context_editor.plan.md)) на самій робочій сесії 8e44a3be закінчився запасним способом «документ» з причиною «the host did not open the assembled transcript». Документ передачі очікував іншу причину: рядки, яких модель уже не бачить. Перевірка `knownResults` у [handoff.ts](../mods/context-editor/hooks/handoff.ts) пройшла, тож збій стався на перемиканні. Розробник питає, чи можна зробити спосіб «транскрипт» придатним для довгих сесій.

## Exploration Log

### Entry 1 — 2026-10-09 — Розбір живого збою (Q1, без прототипу)

**What was tried / researched:**
Транскрипт сесії 8e44a3be (`~/.claude/projects/-home-yavfast-Projects-ClaudeMods/8e44a3be-….jsonl`), сховище редактора, процеси хоста, рядки бінарника хоста VS Code 2.1.289 (`~/.vscode-oss/extensions/anthropic.claude-code-2.1.289-linux-x64/resources/native-binary/claude`).

**Findings:**
- Транскрипт: 1571 рядок, 4.99 МБ, 523 рядки `assistant` і 230 `user`, жодного `compact_boundary`; найбільший рядок — 220 КБ. Модель бачила всю розмову, тому перевірка «rows the model no longer sees» пройшла.
- Між кінцем ходу з `context_handoff` (07:21:26.7) і `/clear` (07:21:27.87) — 1.2 с, з них 1 с `HANDOFF_DELAY_MS`. Спосіб «транскрипт» завершився за ~0.2 с. `/clear` залишив рядок `queue-operation` у транскрипті, `/resume` — жодного.
- VS Code запускає хост як `claude --output-format stream-json --input-format stream-json …`, тобто неінтерактивно (як SDK).
- У хості 2.1.289 команда `resume` оголошена як `{type:"local-jsx", name:"resume", …}` без `supportsNonInteractive`, а `clear` — з `supportsNonInteractive:!0`. `$.command.run` відхиляє команду, якої немає в `commands()` сесії: `$.command.run: no command named /${e} in this session`.
- Код передачі ковтає цю відмову (`io.runCommand('resume', newId).catch(() => undefined)`), тож причина в звіті загальна — «the host did not open the assembled transcript».

**Open questions:**
- Підтвердити наживо, що в режимі stream-json `$.command.run({ command: 'resume' })` відхиляється саме так (і на 2.1.295) — закрито в Entry 2.

### Entry 2 — 2026-10-09 — Живі досліди (Q1–Q3) і розширення VS Code

**What was tried / researched:**
Субагент-дослідник, одноразові плагіни `seeda` (обробник `session.compact`, команди-директиви в промпті) і `seedb` (запит компактизації), малі тестові сесії з `--model haiku`. Режим stream-json, як у VS Code (`-p --input-format stream-json --output-format stream-json --verbose`), на 2.1.295 і на бінарнику VS Code 2.1.289; один інтерактивний прогін у tmux на 2.1.295; читання JS розширення VS Code 2.1.289. Ключові твердження звірено з першоджерелами: рядок заглушки в бінарнику 2.1.289 і журнал плагіна.

**Findings:**
- **Q1 підтверджено на обох версіях.** У stream-json `$.command.list()` має `clear` і `compact`, але не `resume`; `$.command.run({ command: 'resume' })` → `$.command.run: no command named /resume in this session`. `clear` працює: `session.end` з `reason = clear`, новий id. У звичайному `claude -p "<prompt>"` після останнього ходу `$.command.*` відхиляється: «no session is bound in this process».
- **`$.session.compact` у неінтерактивному хості не працює взагалі** (2.1.289 і 2.1.295): «not available in a headless (-p / SDK) session yet: compaction here runs inside a turn (a /compact prompt); catch it and carry on». Натомість `$.command.run({ command: 'compact', args })` працює; обробник бачить `trigger: 'manual'` і `instructions` = `args`.
- **`command.run('compact')` не пропускає хуки самого плагіна-ініціатора** (stream-json і інтерактивно): один плагін може і запросити компактизацію, і обробити її. Пропуск «re-entry» стосується лише `$.session.compact`.
- **Q2 — так.** Послідовність `$.command.run({ command: 'clear' })` → `$.command.run({ command: 'compact', args: MARKER })` → обробник `session.compact` відповідає зібраними рядками (промпт, `tool_use` Read, `tool_result` з KEY_7781, текст). Компактизація йде на щойно очищеній сесії (на вході один рядок — сама команда `/clear`). Модель бачить засіяні рядки: називає ключ і виклик Read, у TUI виклик показано як «Read 1 file». 402 рядки (200 пар Read по ~1.6 КБ) пройшли за ~40 мс; модель знайшла ранній і пізній ключі, нарахувала 200 викликів.
- **Q2, транскрипт нової сесії:** рядки `/clear`; `system` `compact_boundary` з `parentUuid: null`, `logicalParentUuid` на `/clear` і `compactMetadata.trigger: "manual"`; засіяні рядки ланцюжком (асистент — `model: "<synthetic>"`, `origin: { kind: "plugin", name }`, без `toolUseResult` і без `isCompactSummary`); далі рядки команди `/compact` (`<command-args>MARKER</command-args>`, «Compacted»). `claude -p --resume <id>` показує моделі саме засіяні рядки: до межі в ланцюжку нічого немає, тож пастка 7 (`--resume` бачить оригінали) тут не діє.
- **Q2, ціна:** маркер видно моделі — після засіяних рядків стоять рядки команди `/compact MARKER` і «Compacted». Рядки без `handle` втрачають медіа і thinking-блоки (пастка 6); медіа цим шляхом не перевірено.
- **Q3 — так.** Після вбудованої `/compact` `$.session.messages()` віддає весь транскрипт (спершу рядки до межі з оригінальними id), далі підсумок рядком `user` («This session is being continued from a previous conversation…»), копію останнього тексту асистента, рядки команди і хвіст; позначки межі в рядках немає. `{ as: 'api' }` починається з підсумку, далі копія тексту, потім повідомлення `user` з `<system-reminder>` — вбудована компактизація знову вкладає нещодавно прочитані файли текстом, — і пари хвоста; сусідні повідомлення `user` не злиті.
- **Q3, збирання:** записи з API-подання (підсумок першим текстом `user`, далі пари хвоста; без `<system-reminder>`, команд і thinking; мінімальна схема рядка) `claude -p --resume` приймає; модель називає ключ, що є лише в підсумку, і ключ з результату у хвості. Підсумок містить рядок «read the full transcript at: ~/.claude/projects/…/<старий id>.jsonl» — посилання на неочищений оригінал, його треба прибирати.
- **Розширення VS Code 2.1.289 (код):** `registerUriHandler` обробляє шлях `/open` з `session` (UUID) і `prompt` → `claude-vscode.primaryEditor.open(session, prompt)` — відкриває вкладку з цією сесією. Список минулих розмов сканує `~/.claude/projects/<cwd>/*.jsonl`: файл, записаний ззовні, з'являється, якщо ім'я — UUID, перший рядок не `isSidechain` і є заголовок (customTitle, aiTitle, lastPrompt, summary або перший промпт); файли з `entrypoint` `sdk-*` приховано. Відкриття URI з плагіна (`xdg-open`) не перевірено; схема для VSCodium, ймовірно, `vscodium://`.

**Open questions:**
- Чи переживають шлях Q2 медіа (рядки без `handle`) — і чи можна повернути з обробника рядки з `handle` старої сесії після `/clear`.
- Чи можна сховати рядки команди `/compact MARKER` (напр. відмовою в `session.append`).
- Чи відкриває URI розширення сесію, якщо його викликати з плагіна.
- Чи справді правки редактора не застосовувалися у VS Code — підтверджено в Entry 3.

### Entry 3 — 2026-10-09 — Збереження після `--resume`, медіа, маркер; жива перевірка редактора у VS Code

Після рішення розробника про універсальний варіант (схема S) — два додаткові питання до дизайну. Хост 2.1.295, `--model haiku`, stream-json і TUI.

**What was tried / researched:**
- E1: звичайна сесія з двома Read (a.txt — KEY_A_4411, b.txt — KEY_B_5522); компактизація через `command.run('compact', MARKER)` з обробником, що замінює результат a.txt підсумком; потім `claude -p --resume` у новому процесі. Варіанти: решта рядків з `handle` («edit-h») і всі рядки з результатами перезібрані без `handle` («edit-r», як у редакторі); копії файлу з однією зміною. Для порівняння — старий шлях `$.session.compact` з другого плагіна в TUI.
- E2: Read `zebra.png`, `lion.png`, `otter.pdf` з видимими словами; рядки з `handle`, перезібрані рядки з блоком зображення в `toolResults[].result`, рядки з `handle` попередньої сесії після `/clear`; `$.session.append` з блоком зображення.
- Маркер: хук `session.append`, що переписує вміст рядків команди `/compact`.
- Жива перевірка основного шляху редактора в цій сесії (VS Code 2.1.289): три правки `context_edit` у черзі, кінець ходу.

**Findings:**
- **E1 — ні** (висновок замінено Entry 6 на 2.1.295: причина, найімовірніше, шлях (б) — див. «Узгодження з Entry 3» в Entry 6; заново не проганялось). Живий наступний хід бачить правку (`UNKNOWN; KEY_B_5522`), але `--resume` показує оригінали (`KEY_A_4411`) обома шляхами компактизації, з `handle` і без. Хост пише `compact_boundary` з `parentUuid: null` і `compactMetadata.trigger: "manual"` (навіть для `trigger: 'plugin'`), лишає оригінали перед межею і пише повернені рядки копіями з новими `uuid`. Ланцюжок від останнього рядка в «edit-r» до межі оригіналів не торкається — і все одно `--resume` їх повертає. Без `logicalParentUuid` чи з `isCompactSummary` — так само; лише фізично видалені рядки перед межею дають `UNKNOWN`. Отже, завантажувач відновлення бере рядки перед межею з файлу іншим шляхом, ніж `parentUuid`. Обмеження [C_CTX_DEC_05](./context_editor.concept.md#C_CTX_DEC_05) лишається; засів після `/clear` переживає `--resume` лише тому, що перед межею немає нічого, крім `/clear`.
- **E2 — медіа шляхом S не проходить.** З `handle` у тій самій сесії модель бачить усі три файли. Рядок без `handle` доходить до моделі лише текстом і блоками інструментів: `toolResults[].result` ігнорується, зображення зникає (API-подання: `tool_result` порожній). `handle` з попередньої сесії хост мовчки вважає невідомим і будує рядок з полів — медіа зникає без помилки. `$.session.append` з зображенням: «a image block the conversation does not take from a plugin». Задокументованого способу повернути байти зображення в розмову з плагіна немає; лишаються архів медіа з шляхом у тексті (модель читає файл знову) або власний інструмент мода, чий результат несе зображення (не перевірено).
- **Маркер — частково.** Хук `session.append` не може відхилити рядки команди (`door=command`), але може переписати їхній вміст: аргументи `/compact` зникають і з рядка, і з API-подання. Рядки-застереження і «Compacted» лишаються (переписати їх, імовірно, можна так само — не перевірено).
- **Жива перевірка редактора у VS Code — підтверджено.** Правки, поставлені о 10:53, через 12 хвилин досі в черзі; у транскрипті немає ні межі компактизації, ні промпту продовження, при цьому `editor-ready` оновлюється. Основний шлях редактора в неінтерактивному хості не працює.

**Open questions:**
- Чи переписуються рядки-застереження і «Compacted» тим самим хуком.
- Чи працює повернення медіа власним інструментом мода (результат MCP з блоком `image`).

### Entry 4 — 2026-10-09 — Події ходу від команд мода, час завершення команди, черга, мітка в рядках команди

Після рев'ю дизайну фази 10 (раунд 10): специфікація спиралась на неперевірені факти. Хост 2.1.295, `claude` у stream-json і в TUI; один прогін stream-json на 2.1.289 дав ті самі події (2.1.289 більше не підтримується — рішення розробника 2026-10-09: «Прив'язуватись до старих версій нема сенсу»).

**What was tried / researched:**
Плагін `seedx` з журналом усіх `session.start`, `turn.start`, `prompt.submit`, `tool.call`, `turn.complete`, `session.compact` (початок і кінець), `session.append` (door, origin, текст), `session.end` і часу до та після кожного `$.command.run`. Команди `/clear`, `/compact MARKER` (з рядками і з `{skip}`), команда посеред повільного ходу (`sleep 8`) — з таймера, створеного в хуку `tool.call`, і з таймера опитувача, запущеного в `session.start`; промпт людини, що цитує мітку.

**Findings:**
- **Команди мода не породжують подій ходу.** Ні `/clear`, ні `/compact` (з рядками чи `skip`) не дають `prompt.submit`, `turn.start` чи `turn.complete` — в обох хостах. Видно лише `session.end` (для `/clear`) і рядки `session.append`.
- **`command.run` завершується після роботи.** `compact`: початок обробника → кінець обробника (+500 мс сну) → завершення виклику (+33 мс); значення `{}` або `{ text: "Not compacted · <причина>" }`. `clear`: `session.end reason=clear` → завершення виклику; `$.session.id()` уже повертає новий id.
- **Черга залежить від походження таймера.** Таймер, створений у хуку `tool.call`, відхиляється й через 2 с: «command.run: called from a tool.call hook, it would wait on the turn this hook is holding». Таймер з ланцюжка поза хуком, на який чекає хід (опитувач із `session.start`; у спайку схеми B — пауза після `turn.complete`), стає в чергу: команда чекає кінця ходу і виконується одразу після `turn.complete`.
- **Повідомлення людини посеред ходу вливається в цей хід** (`prompt.submit` з `turnId` поточного ходу, доставка вкладенням), окремого ходу не буде; команда в черзі виконується після кінця цього ходу.
- **Мітка в рядках команди.** Обробник завжди бачить `instructions` = аргументи команди; хук `session.append` їх не змінює. У stream-json рядки команди (`door=command`) проходять через `session.append` після компактизації, і їх можна переписати. **У TUI рядки команди і копії після межі пишуться у файл повз `session.append`**; хуку видно лише один рядок поза ланцюжком `door=prompt` «/compact <аргументи>» перед компактизацією. Сховати мітку в TUI неможливо.
- **У stream-json кожен рядок, повернений обробником компактизації, знову проходить через `session.append`** з `origin { kind: 'plugin', name: <плагін, що запустив /compact> }`; рядки промптів — `door=prompt`. Хук, що реагує на нові рядки (автотегування), спрацює на ці копії.
- **Промпт людини з цитатою мітки** дає `prompt.submit` з `origin` `sdk` (stream-json) або `composer` (TUI) і `turn.start` з тим самим текстом; рядки команд мода мають `origin { kind: 'plugin' }`.

### Entry 5 — 2026-10-09 — Незмінене медіа після компактизації (знахідка C Verify фази 10)

**What was tried / researched:**
Хост 2.1.295, haiku, TUI і stream-json. Два Read зображень в одній відповіді — без попереднього рядка і з рядком тексту перед ними; варіанти обробника: поточний мод (v0), усі незмінені рядки з `handle` (vB), старий `$.session.compact` з другого плагіна (vC), збереження рядка `tool_use` зміненої пари з її id (vS), перезбирання решти рядків асистента відрізка (vR, vF).

**Findings:**
- Причина — злиття рядків асистента за `message.id`: перезібраний рядок отримує синтетичний id і розриває відповідь, а пізніший рядок тієї ж відповіді з `handle` хост приєднує до ранішого повідомлення — його `tool_use` лишається без сусіднього результату («Tool result missing due to internal error»). Відтворюється в TUI і в stream-json, лише коли перед викликами є рядок тексту або thinking.
- v0, vB, vC — FAIL (отже, шлях компактизації ні до чого); vS, vR, vF — PASS в обох хостах. Батько до межі в копії результату (пункт 5 навички) не шкодить у жодному варіанті.
- `claude -p --resume` у жодному варіанті не дав порожньої розмови (оригінали повертаються — відома пастка 7).

**Open questions:**
- collapse і rewrite після рядка thinking передбачено тим самим механізмом, наживо не перевірено.

### Entry 6 — 2026-10-09 — Межа після `--resume` і перезавантаження модуля (знахідка G Verify фази 10)

**What was tried / researched:**
Хост 2.1.295, haiku, TUI і stream-json; копія мода плюс окремий плагін-зонд (дампи `messages()`, `{as:'api'}`, збіг Boundary, кандидати ідентичності процесу на кожному промпті, кінці ходу й компактизації). Сесії: A — лише текст (summarize одного з двох Read); B — змінена пара між двома зображеннями з `handle`; L — 10 Read по 32 КБ (~186k токенів), collapse і summarize з відновлених процесів.

**Findings:**
- Відновлення йде по `parentUuid` до `compact_boundary`; оригінали повертаються через батька до межі в копіях рядків з `handle` (B: правка втрачена, зображення двічі) і через злиття за `message.id` (A: правка жива, але `tool_use` дублюється й повертається вилучений `context_list`). L (лише текст) — чисто.
- У відновленому процесі `messages()` — завантажений ланцюжок; збережена межа в A/B не збіглася (дублікати), і запасний шлях «увесь транскрипт» — саме те, що бачить модель. У тому самому процесі (і після гарячого перезавантаження) межа збігалась у правильному місці, і хвіст 1:1 за id відповідав API-поданню.
- Ідентичність процесу: pid і час старту батьківського процесу оболонки (`$PPID`) — стабільні при перезавантаженні модуля, нові після перезапуску; токен `$.env.set` — так само.
- Q5: на ~186k токенів `{as:'api'}` містить усі результати; хост має два механізми очищення вмісту старих результатів (id лишаються). Відмову в сесії a3902d56 (`collapse #4..#110`) пояснює не це, а умова `earlyPrompt` (edits.ts): згортання з промптом людини раніше за перший рядок з відомим результатом відхиляється, навіть коли вікно API покриває всю розмову — відтворено модульним тестом.

**Узгодження з Entry 3 (E1):** E1 бачив оригінал після `--resume` і у варіанті «edit-r», де ланцюжок від останнього рядка до межі оригіналів не торкався, і звідти зробив висновок, що завантажувач бере рядки перед межею іншим шляхом. За цим Entry найімовірніша причина — шлях (б): у «edit-r» рядки асистента з викликами `tool_use` лишалися з `handle` і мали той самий `message.id`, що й оригінали до межі, тож відновлення підтягнуло їх разом із результатами. Висновок E1 замінено (2.1.295, цей Entry); E1 заново не проганявся. Чинна модель: відновлення йде по `parentUuid` до межі, а оригінали повертаються лише шляхами (а) і (б) (навичка plugin-hooks, пункт 7).

**Open questions:**
- Правки компактизації командою й відновлення сесії з медіа (повернення оригіналів, дублікати `tool_use`) — відоме обмеження C_CTX_DEC_05 з новими деталями; надійний шлях — передача засівом.

## Conclusion

**Verdict:** concluded. Живий тест упав не через довжину сесії, а тому, що хост VS Code неінтерактивний: `/resume` там недоступний для `$.command.run`. Спосіб «транскрипт» можна зробити придатним і для VS Code, і для довгих сесій: засіяти очищену сесію компактизацією (схема S) з записами, зібраними з того, що бачить модель (API-подання). Вибір схеми — за розробником ([C_CTX_DEC_11](./context_editor.concept.md#C_CTX_DEC_11)).

**Key constraints discovered:**
- Неінтерактивний хост (VS Code, SDK, `-p`): немає `/resume`; `$.session.compact` завжди відхиляється; працює `$.command.run({ command: 'compact', args })` з `trigger: 'manual'`.
- `command.run('compact')` запускає хуки самого ініціатора — розділення на два плагіни на цьому шляху не потрібне.
- Компактизація від обробника на очищеній сесії пише `compact_boundary` з `parentUuid: null`, і `--resume` бачить лише повернені рядки.
- У звичайній сесії `--resume` іде по `parentUuid` до межі: текстові правки з перезібраною цілою відповіддю переживають відновлення, а оригінали можуть повернутися через копію рядка з `handle` (батько до межі) або через рядки асистента з тим самим `message.id` (Entry 6; висновок Entry 3 E1 замінено).
- Рядки команди `/compact` з `args` видно моделі; підсумок вбудованої `/compact` містить шлях до старого транскрипту.
- Команди мода (`/clear`, `/compact`) не породжують подій ходу; `command.run` завершується після роботи; команда стає в чергу до кінця ходу, якщо таймер не створено в хуку, на який чекає хід (Entry 4).
- У TUI рядки команди і копії після межі оминають `session.append` — мітку не сховати; у stream-json повернені рядки проходять через `session.append` з `origin: plugin` (Entry 4).
- Хост ≥ 2.1.295: старіші версії не підтримуються (рішення розробника).

**Recommendations for the concept:**
- **Поза спайком, але важливо:** основний шлях редактора (правки через тригер) у VS Code, найімовірніше, не працює — тригер кличе `$.session.compact`, а обробник слухає лише `trigger: 'plugin'`. Перевірити наживо і, якщо так, перейти на `$.command.run({ command: 'compact', args: MARKER })` з обробником для `manual` + MARKER (окреме виправлення з концептом/специфікацією).
- Для передачі розглянути схему S як основну замість T (або T у TUI і S у неінтерактивному хості), з маркером, що сам пояснює, що сталося.
- Джерело записів — API-подання (те, що бачить модель): прибирати `<system-reminder>`, команди, рядок із шляхом до старого транскрипту; правки зіставляти з ним через `tool_use_id`, як уже робить `collectMedia`.
- Не ковтати відмову `$.command.run`: її текст має потрапити в причину звіту.
- Медіа на шляху S не проходить (Entry 3): незмінені медіа — в архів сховища, у тексті рядка — опис і шлях, щоб модель могла прочитати файл знову.
