## 1. Що це і модель мислення

context-mode — MCP-сервер разом із набором хуків хоста (Claude Code й ще 16 хостів). Він не дає сирому виводу інструментів потрапити у вікно контексту моделі і зберігає хід роботи через компактизацію. README називає це «другою половиною проблеми контексту»: знімок Playwright коштує 56 KB, двадцять issue GitHub — 59 KB, і за пів години роботи зникає 40 % контексту (твердження джерела); після компактизації агент забуває файли, задачі й останній запит.

Модель мислення — **«LLM генерує код, а не обробляє дані»**. Сирі дані живуть у підпроцесі-пісочниці або в локальному пошуковому індексі; у контекст потрапляє лише те, що модель свідомо надрукувала або знайшла пошуком. Модель туди спрямовують жорстко (хуки, що відхиляють чи переписують виклик інструмента до його виконання) і м'яко (блок правил маршрутизації на старті сесії, файли інструкцій, навичка).

Це **запобігання на вході, а не правка після факту**: уже записане в транскрипт context-mode ніколи не переписує, хук після виклику інструмента в Claude Code лише записує подію. Компактизацію він переживає так само: у контекст повертається не дамп подій, а короткий зміст, кожен розділ якого несе готовий пошуковий запит за подробицями.

## 2. Концепти

**2.1. Виконання в пісочниці («думати кодом»).** Агент пише скрипт, який виконується в окремому підпроцесі (12 мов), і в контекст повертається лише stdout. Навіщо: один скрипт замінює десятки читань і викликів оболонки, сирий вивід яких інакше осів би в контексті. Автентифіковані CLI успадковують середовище, вивід обмежено жорсткою стелею з примусовим завершенням. Де: `src/executor.ts`, `src/runtime.ts`. Твердження джерела: 56 KB → 299 B; 47 читань (700 KB) проти одного виклику (3,6 KB).

**2.2. Обробка файлу без читання в контекст.** Файл завантажується в змінну всередині пісочниці, код друкує лише результат. Правило для моделі: «читаєш, щоб редагувати — читай; читаєш, щоб аналізувати — обробляй у пісочниці». Шлях обмежено межами проєкту. Де: `src/server.ts`. Твердження: 45 KB → 155 B.

**2.3. Вивід за порогами розміру: пошук за наміром і винесення в індекс.** Малий вивід (до 5 KB) повертається як є. Більший, коли агент указав намір, індексується повністю, а повертаються лише заголовки розділів, однорядкові уривки і список «термінів для пошуку». Дуже великий без наміру індексується, а агент отримує вказівник «проіндексовано N розділів, шукай так-то». Навіщо: результат інструмента стає активом, який можна дістати, а не обрізаним текстом — нічого не губиться. Де: `src/server.ts`.

**2.4. Пакетний збір.** Кілька позначених команд виконуються за один виклик (за потреби паралельно), увесь вивід індексується, а запити до нього обробляються в тому ж колі. Навіщо: уникнути і повені виводу, і багатьох дрібних кругів. Твердження: 986 KB → 62 KB на дослідженні репозиторію.

**2.5. База знань сесії.** Markdown ріжеться за заголовками (блоки коду цілі), JSON — за шляхами ключів, усе — у SQLite FTS5. Ранжування BM25 із вагою заголовків, два зіставлення паралельно (стемінг і триграми) зливаються Reciprocal Rank Fusion, далі — переранжування за близькістю, виправлення одруків і уривки навколо збігів замість перших N символів. Сховище на проєкт, дані старші за 14 днів чистяться на старті. Навіщо: повертати точні шматки замість підсумку — джерело свідомо приймає меншу економію (82 % проти 98 % у обробки файлу), бо точний код кращий за переказ. Де: `src/store.ts`, `src/search/unified.ts`.

**2.6. Завантаження сторінки з індексуванням і кешем.** URL завантажується, HTML перетворюється на markdown, індексується, повертається короткий уривок; повторне завантаження протягом доби дає підказку «вже є» замість десятків KB. Захист від SSRF (адреси метаданих хмари, link-local, за прапорцем — приватні мережі).

**2.7. Маршрутизація до виконання (перехоплення виклику інструмента).** Для кожного інструмента одна функція вирішує: відхилити, переписати вхід, додати пораду, спитати людину або пропустити. Виклик curl/wget у stdout і HTTP-код в оболонці **переписуються** на `echo` з інструкцією «перенаправлено, клич інструмент пісочниці»; збирачі Gradle/Maven ідуть у пісочницю; команди зі структурно обмеженим виводом (`pwd`, `git status`, `--version` без каналів і перенаправлень) проходять без поради; решта — з порадою раз на сесію. Великі читання файлів рахуються як уникнуті байти. Де: `hooks/core/routing.mjs`, `hooks/pretooluse.mjs`.

**2.8. Дозування порад.** Поради звучать раз на сесію (атомарно між процесами через файли-маркери), а для чужих MCP-інструментів — періодично, кожні N викликів, бо «раз на сесію» губилось після компактизації. Навіщо: тримати пораду у свіжому вікні, не засмічуючи контекст повторами.

**2.9. Деградація, коли MCP-сервер не готовий.** Будь-яке перенаправлення до власних інструментів пропускає виклик як є, якщо сервер не підтвердив готовність свіжим файлом-маркером. Навіщо: агента ніколи не посилають до інструмента, якого він не може викликати.

**2.10. Правила для субагентів.** Під час запуску субагента блок маршрутизації дописується до його промпту (разом із кроком завантаження відкладених інструментів), а субагент типу «лише оболонка» мовчки підвищується до загального, щоб мати MCP-інструменти. Навіщо: субагент не отримує контексту старту сесії. Твердження: 94 % економії на дослідженнях субагентів.

**2.11. Журнал подій сесії.** Хуки після виклику інструмента, промпту людини і кінця ходу виділяють типізовані події з пріоритетами в SQLite на проєкт, без виклику моделі: файли, задачі, плани, рішення й поправки людини, правила з файлів інструкцій, помилки з парами «помилка → виправлення», git, середовище, знахідки субагентів, цикли повторів (той самий інструмент тричі й більше), відхилені людиною підходи, вставлені дані. Секрети в аргументах маскуються до запису. Де: `src/session/extract.ts`, `src/session/db.ts`.

**2.12. Переживання компактизації: знімок, директива, пошук.** Перед компактизацією будується знімок; після неї старт сесії вводить блок маршрутизації, «путівник сесії» (останній запит, задачі, рішення, змінені файли, невирішені помилки) і короткий блок пріоритетного (роль → останні рішення → навички → намір). Знімок — **зміст, а не підсумок**: кожен розділ має короткий опис і готовий пошуковий запит за подробицями, а самі події індексуються як окреме джерело. Навіщо: тягнути пам'ять на вимогу, а не штовхати її в контекст. Де: `hooks/precompact.mjs`, `hooks/sessionstart.mjs`, `src/session/snapshot.ts`.

**2.13. Семантика відновлення і межа «етапу продовження».** Новий запуск без продовження стирає дані попередньої сесії («чистий аркуш»); відновлення бере живі події сесії, а коли їх немає (нова ідентичність після відновлення) — останній неспожитий знімок проєкту; події попереднього продовження відтинаються, щоб завершене раніше не виглядало поточним. Великі дані в знімку — однорядкові вказівники.

**2.14. Пошук по пам'яті з кількох джерел.** Один пошук зливає за часом базу знань, журнал подій і пам'ять хоста (файли інструкцій, каталог пам'яті). Правила кажуть моделі після відновлення **шукати, перш ніж питати людину**, з фіксованими мітками джерел (компактизація, промпт людини, рішення, відхилений підхід, обмеження).

**2.15. Захист від повені пошуку.** Багато пошуків за хвилину поступово урізають видачу, далі — відмова з порадою пакетувати. Лічильник ведеться на кожен контекст агента окремо, щоб паралельні субагенти не ділили один бюджет.

**2.16. Облік економії і ціни.** Окремо рахуються уникнуті байти (оцінки за замовчуванням для перенаправлень, справжні розміри для великих читань і читань усередині пісочниці), повернуті і витрачені на пошук; ADR-0004 фіксує формулу «без = уникнуте + повернуте; з = повернуте». Каталог цін на модель з цінами кешу дає «зекономлено $», рядок стану читає файл-супутник кілька разів на секунду. Де: `src/session/analytics.ts`, `src/session/pricing.ts`, `docs/adr/0004-…`.

**2.17. Повторне використання політики безпеки хоста.** Правила дозволу й заборони Claude Code застосовуються і всередині пісочниці, зчеплені команди перевіряються частинами, заборона перемагає; за замовчуванням безпека відкрита, суворий режим — за змінною середовища.

**2.18. Тексти описів і відмов як інженерна поверхня.** ADR-0002 фіксує структуру опису інструмента (заголовок / КОЛИ / КОЛИ НІ / ПОВЕРТАЄ / ПРИКЛАД) і перевіряє її контрактним тестом. ADR-0003: перенаправлення не має звучати як заборона — слово «blocked» змусило Opus 4.6 здаватися (6/6 → 0/6 після переформулювання); тексти тепер кажуть «перенаправлено до X; X має повний доступ; клич X зараз». Наказова форма водночас покращила точність параметрів у малих моделей, тож переписування тексту перевіряють пробами, а не роблять усе м'якшим.

## 3. Архітектура

- **Шари.** MCP-сервер з обробниками інструментів (один великий модуль), база знань, модулі сесії (журнал, виділення подій, знімок, аналітика), хуки — звичайний JS без збирання, кожен обгорнутий так, щоб ніколи не блокувати сесію (помилки — у лог), адаптери хостів за одним інтерфейсом (розбір і формат кожного виду хука, налаштування, каталоги, файли інструкцій, перевірки здоров'я).
- **Інтеграція з Claude Code** — командні хуки: перед викликом інструмента (оболонка, веб, читання, пошук, запуск агента, власні й чужі MCP-інструменти), після виклику (лише запис), промпт людини (лише запис), кінець ходу (маркер і ціна ходу з хвоста транскрипту), перед компактизацією (знімок), старт сесії (правила, путівник, знімок). 11 MCP-інструментів, навичка з деревом рішень маршрутизації і службові команди-навички.
- **Стан.** Журнал і база знань — SQLite на проєкт, безпечні для кількох записувачів (ADR-0001 відмовився від ексклюзивного замка, що ламав роботу в кількох вікнах).
- **Багато хостів.** 17 адаптерів з оцінкою повноти; заява джерела — ~98 % економії з хуками, ~60 % лише з файлами інструкцій. На хостах Pi/OMP контекст додається повідомленням **у кінець**, а не в системний промпт, щоб зберегти кеш префікса — єдине явне рішення про кеш промпту в репозиторії.
- **Компроміси.** Запобігання залежить від того, чи модель слухає перенаправлення і чи хуки покривають виклик; вивід чужих MCP-інструментів у Claude Code після факту не зменшити; байти для перенаправлень — оцінки.

## 4. Що незвичне

- Команду оболонки переписують на `echo` з інструкцією, а не відхиляють: інструмент «вдається», а його вивід — перенаправлення.
- Результат компактизації — зміст із пошукових запитів, а не підсумок.
- Формулювання відмов перевіряють експериментально («blocked» проти «redirected», емодзі в описах шкодять, м'якше не завжди краще).
- Субагент «лише оболонка» мовчки підвищується до загального.
- Нова сесія без продовження стирає дані попередньої.
- README і код розходяться: README обіцяє знімок ≤ 2 KB з відкиданням нижчих пріоритетів, код знімка будує всі непорожні розділи без бюджету; CONTRIBUTING називає базу знань тимчасовою на процес, README — постійною на проєкт з терміном 14 днів.
- «Нічого не залишає машину» з README не зовсім так: за наявності ключа API в налаштуваннях міст платформи пересилає кожну подію (замасковану) на хостинговий сервіс аналітики. Це за явною згодою, і значна частина свіжого коду існує для нього.

## 5. Напрям руху

Травень–червень 2026 (1.0.130 → 1.0.169): вимірювання й FinOps (каталог цін, ціна ходу на всіх адаптерах, кілька виправлень формули «з / без», хостингова аналітика), ширше покриття хостів і живучість процесів (Windows, Pi/OMP), коректність продовження (застарілі події, бюджет пошуку на агента, вказівники замість вбудованих даних), менше хибних перехоплень (список обмежених команд, поріг розміру), посилення безпеки (межа проєкту, SSRF).

## 6. Заявлені обмеження й не-цілі

- Не-ціль — диктувати стиль мови моделі: правила кажуть, куди йдуть дані, а не як говорити (джерело посилається на дані, що вимоги стислості шкодять результатам).
- Без хуків правила лише порадчі; один не перенаправлений виклик «з'їдає економію сесії»; частина хостів не має хуків або не дає змінити вивід інструмента.
- Хук після виклику не спрацьовує для власних MCP-інструментів плагіна — звідси міст через файл-маркер.
- Виконання в пісочниці має доступ процесу до файлової системи; до проєкту прив'язана лише обробка файлу.
- Файли маршрутизації більше не пишуться в проєкти автоматично — засмічували git.
